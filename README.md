# 작은 사회 · 학교 시민생활

기존 작업의 원본 요구사항과 구현을 이어받은 React / TypeScript / Firebase 웹앱입니다.
요구사항: `docs/requirements.txt`, 전체 설계: `docs/IMPLEMENTATION_PLAN.md`.

## 실행

```sh
npm ci
npm run dev
```

현재 Firebase 프로젝트 `jobedu-5c8fb`의 웹앱 설정은 로컬 `.env.local`에 반영했습니다.
Firebase Authentication, Firestore DB, 보안 규칙, 최초 학교/관리자 등록은 각각 별도 설정입니다.
웹앱 설정만으로 계정이나 DB가 생성되지는 않습니다.

로그인 아래 **가상 시민으로 직업 체험하기**에서 학생 신청 → 교사 체험 → 신청 승인 → 학생 내 직업을 확인할 수 있습니다. 데모는 메모리만 사용하며 실제 Firebase 쓰기를 호출하지 않습니다.

학생 화면은 지도형 홈(`마이페이지`/`은행`/`상점` 등 건물 hotspot)이며, 실제로 동작하는 기능은 지도의 **마동초등학교(마이페이지)** 건물에 연결되어 있습니다. 다른 건물은 아직 "다음 단계에서 연결됩니다" 안내만 표시합니다.

## 현재 구현

- 학교별 멤버십, 학생/교사 분기, 시민증, 명단 가져오기 검증
- 4국 분류, 기본 직업 6개, 교사 직업 생성/수정/상태/권장 학년 설정
- 학생 자기 신청, 교사 승인/반려, 복수 직업 배정, 배정 종료
- 업무 템플릿 생성, 자격 있는 학생에게 배정, 학생 제출 → 교사 승인/다시 제출 요청 → 완료 후 재시작
- 직업별 월급 설정, 교사의 월별 정산(미리보기 → 확정), 계좌·불변 원장·학생 자기 명세 조회
- 사업·상품 등록(교사), 학생의 즉시 구매(가격·재고·잔액 서버 검증, 재고 경쟁 시 하나만 성공)
- 시민광장: 직업/사업 구조화 제안서 제출 → 교사가 투표 개시(마감·참여율·찬성 기준 설정) → 1인 1표 비공개 투표 → 교사 집계 → 승인 시 실제 직업/사업 생성
- 학교별 데이터 격리, 서버 시각/필드 검증, 중복 신청 방지
- 승인과 배정 트랜잭션, 핵심 직업 해제/삭제 금지, 종료 직업 신규 배정 금지
- 제공된 배경 및 국·직업 아이콘, 지도형 학생 홈, 태블릿/모바일 레이아웃

## 후속 구현

사진 인증·통계·명단 갱신 등 운영 기능은 원본 계획의 7~8단계입니다.
목록은 최대 100건, 국 명칭은 공통 템플릿입니다. 대규모 페이지 조회·학교별 국 이름 편집·직업 정원·배정 기간 이력은 후속 운영 범위입니다.
신청은 학생/직업당 한 번이며 반려 후 재신청 버전 관리는 후속 단계입니다.
배정 문서는 학생/직업의 현재 상태를 나타내며 종료 후 재배정하면 시작 시각이 갱신됩니다. 과거 기간별 이력은 아직 제공하지 않습니다.
업무는 인증 방식 중 결과물 제출(artifact)만 실제로 동작합니다. 사진·자동 인증은 다음 단계입니다. 제출 이력도 현재 문서 1건에 최신 시도만 보존하며, 시도별 이력을 남기는 별도 컬렉션은 후속 단계입니다(`docs/DECISIONS.md` 참조).
금융은 월급 정산과 즉시 구매만 구현되어 있습니다. 저축·대출·세금·과태료와 학생이 직접 신청하는 `financialRequests`/은행원 학생 검증 워크플로는 아직 없습니다(`docs/DECISIONS.md` D-17~D-21).
사업 운영 학생의 자기 상품 관리·매출 열람은 아직 없습니다(`docs/DECISIONS.md` D-22~D-25). 상품은 1개씩만 구매할 수 있습니다.
시민광장은 직업·사업 제안만 지원합니다. 규칙·행사·커뮤니티 제안, 초안 저장, 시민 의견(댓글)은 아직 없습니다(`docs/DECISIONS.md` D-27~D-32).

학생 실명 명단, 사진, 금융정보는 배포 자산에 포함하지 않습니다.
