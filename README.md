# 작은 사회 · 학교 시민생활

기존 작업의 원본 요구사항과 구현을 이어받은 React / TypeScript / Firebase 웹앱입니다.
요구사항: `docs/requirements.txt`, 전체 설계: `docs/IMPLEMENTATION_PLAN.md`.

## 실행

```sh
npm ci
npm run dev
```

현재 Firebase 프로젝트 `jobedu-5c8fb`의 웹앱 설정은 로컬 `.env.local`에 반영했습니다.
Firebase Authentication, Firestore DB, 보안 규칙, 최초 학교/관리자 등록은 각각 별도 설정입니다.
웹앱 설정만으로 계정이나 DB가 생성되지는 않습니다.

로그인 아래 **가상 시민으로 직업 체험하기**에서 학생 신청 → 교사 체험 → 신청 승인 → 학생 내 직업을 확인할 수 있습니다. 데모는 메모리만 사용하며 실제 Firebase 쓰기를 호출하지 않습니다.

학생은 이메일이 필요 없습니다. 로그인 화면의 "학생" 탭에서 **학교 코드·학년·이름 + 비밀번호**로 로그인합니다(내부적으로만 합성 이메일을 만들어 Firebase Auth에 전달, `docs/DECISIONS.md` D-44). 교사는 기존처럼 이메일로 로그인합니다. 태블릿 URL에 `?school=학교코드`를 붙여 두면 학생은 학년·이름·비밀번호만 입력하면 됩니다. (학년당 반이 하나뿐인 학교 기준입니다 — 학년당 반이 여러 개면서 동명이인이 있는 학교는 `create-student-accounts`가 충돌을 감지해 알려줍니다.)

## 계정 만들기 (관리자 도구)

멤버십 쓰기는 앱에서 전부 거부되어 있어(D-5), 학교·교사·학생 로그인 계정은 서비스 계정 키로 실행하는 오프라인 스크립트로 만듭니다:

```sh
node scripts/admin-bootstrap.mjs create-school --key <service-account.json> --school jobedu-5c8fb --name "마동초등학교"
node scripts/admin-bootstrap.mjs create-teacher --key <service-account.json> --school jobedu-5c8fb --email teacher@example.com --password <비밀번호>
node scripts/admin-bootstrap.mjs create-student-accounts --key <service-account.json> --school jobedu-5c8fb --code madong [--password <신규 계정 공통 비밀번호>]
node scripts/admin-bootstrap.mjs reset-student-password --key <service-account.json> --school jobedu-5c8fb --code madong --grade <학년> --name <이름> [--password <새 비밀번호>]
```

`--code`(학교 코드)는 학생이 로그인 화면에서 입력하는 값으로, Firestore의 `--school` 아이디와 별개로 우리가 정하는 아무 문자열이면 됩니다(예: `madong`). 태블릿 URL에 `?school=madong`을 붙여두면 학생은 학년·이름·비밀번호만 입력하면 됩니다.

`create-student-accounts`는 같은 학년에 동명이인이 있는지 먼저 검사한 뒤(있으면 알리고 중단), 이미 명단 가져오기(RosterImport)로 등록된 학생마다 계정이 없으면 만들고 학년·이름·비밀번호를 `student-accounts.csv`로 출력합니다(재실행해도 기존 계정은 건너뜁니다). `--password`를 주면 이번에 새로 만드는 계정 전부가 그 비밀번호로 생성됩니다(테스트용 — 자동 생성되는 임의 6자리 비밀번호 대신). 서비스 계정 키(`*firebase-adminsdk*.json`)와 이 CSV는 `.gitignore`에 이미 포함되어 있습니다 — 그래도 직접 다른 곳에 붙여넣거나 공유하지 마세요.

Firebase는 한 번 설정된 비밀번호를 관리자도 다시 읽어올 수 없습니다(해시만 저장됨). 그래서 이 스크립트가 만들거나 바꾼 비밀번호는 모두 로컬 "비밀번호 장부"(`.student-passwords.json`, git 추적 제외)에 남기고 실행할 때마다 `student-accounts.csv`를 그 장부 기준으로 새로 씁니다 — CSV를 열어보면 항상 각 학생의 최신 비밀번호를 볼 수 있습니다. 특정 학생의 비밀번호를 바꾸고 싶으면 `reset-student-password`를 실행하면 됩니다(서비스 계정 키가 있는 관리자만 실행할 수 있는 오프라인 도구입니다). 교사 계정은 이와 별개로 로그인 후 "운영 현황" 화면에서 스스로 비밀번호를 바꿀 수 있습니다.

학생 비밀번호는 터미널 없이 **앱 안에서도** 바꿀 수 있습니다 — 교사로 로그인해 학생 명단의 "비밀번호 재설정" 버튼을 누르면 됩니다. 여러 명을 한 번에 바꾸려면 명단 화면의 "비밀번호 일괄 변경"에서 구글 시트 링크(`이름,학년,학교코드,비밀번호` 순, `student-accounts.csv`와 같은 열 순서)를 붙여넣으면 됩니다(한 번에 최대 20명, `docs/DECISIONS.md` D-80~D-82). 이건 `cf-worker/`에 배포된 Cloudflare Workers 관리자 엔드포인트가 처리합니다(카드 등록이 필요한 Firebase Cloud Functions 대신 선택함, 배경은 `docs/DECISIONS.md` D-56~D-58 참고). Worker를 다시 배포하려면:

```sh
cd cf-worker
npm install
npx wrangler secret put GOOGLE_CLIENT_EMAIL   # 서비스 계정 client_email
npx wrangler secret put GOOGLE_PRIVATE_KEY_B64 # 서비스 계정 private_key를 base64로
npx wrangler deploy
```

새 교사 계정을 만들거나 기존 교사의 비밀번호를 바꾸는 것도 **앱 안에서** 할 수 있습니다 — 최고 관리자(`owner`) 계정으로 로그인해 "운영 현황" 화면 아래 "교사 계정 관리"에서 처리합니다(일반 `teacher` 계정에는 이 화면이 보이지 않습니다, `docs/DECISIONS.md` D-95). `admin-bootstrap.mjs`로 만든 기존 교사 계정은 이메일 정보가 없어 목록에 "이메일 정보 없음"으로 표시되며, 그 계정들의 비밀번호는 여전히 오프라인 스크립트(`create-teacher`)로만 바꿀 수 있습니다.

학생 화면은 지도형 홈(마이페이지/은행/상점 등 건물 hotspot)입니다. 은행·상점·마이페이지는 각자의 전용 화면(대출·저축·구매·직업·업무·시민광장·과태료)에 연결되어 있고, 나머지 건물(방송부·예술부·도서부·우체부·환경부·행사·문화)은 그 건물이 대표하는 직업 아이콘만 걸러서 직업 둘러보기/신청/배정/오늘의 업무를 보여줍니다(`docs/DECISIONS.md` D-96) — 아직 그 아이콘의 직업이 학교에 없으면 "이 건물에서 맡을 수 있는 직업이 아직 없어요"라고 안내합니다. 28개 직업 아이콘 전부가 실제 직업으로 등록되어 있습니다(D-97).

학생 화면 HUD의 "📖 설명서" 버튼을 누르면 이 앱 사용법과 지도 건물 안내, 부서별 전체 직업 카탈로그를 한 화면에서 볼 수 있습니다 — 학생이 처음 로그인하면 자동으로 한 번 보여주고, 이후에는 버튼으로 언제든 다시 볼 수 있습니다(D-98). 핵심 흐름(지도→신청→오늘의 업무→은행→상점)은 실제 화면 스크린샷 5장과 짧은 문장으로 안내해 초등학교 1학년도 읽을 수 있게 했고, 시민광장 제안·투표·과태료처럼 더 어려운 개념은 별도 문단 한 줄로만 짧게 소개합니다(D-99).

## 현재 구현

- 학교별 멤버십, 학생/교사 분기, 시민증, 명단 가져오기 검증
- 4국 분류(학교별 이름 편집 가능), 기본 직업 6개, 교사 직업 생성/수정/상태/권장 학년/정원 설정
- 학생 자기 신청(반려 후 재신청 가능, 이전 신청 이력 보존), 교사 승인/반려, 복수 직업 배정(정원 초과 시 거부), 배정 종료(종료된 기간 이력 보존)
- 업무 템플릿 생성, 자격 있는 학생에게 배정, 학생 제출 → 교사 승인/다시 제출 요청 → 완료 후 재시작. 시도마다 제출 내용이 별도로 보존되어 이전 제출 이력을 확인할 수 있음
- 직업별 월급 설정, 교사의 월별 정산(미리보기 → 확정), 계좌·불변 원장·학생 자기 명세 조회
- 저축 상품 설정(교사, 단기·장기 프리셋), 학생의 즉시 가입(원금·기간·잔액 서버 검증), 교사의 만기 정산(미리보기 → 확정, 원금+이자 지급, 만기 전 정산은 Rules에서도 차단)
- 대출 상품 설정(교사, 단기·장기 프리셋, 저축과 같은 상품 관리 화면 공유), 학생의 신청(목적·상환계획) → 교사의 검토자 지정 → 배정된 학생의 은행원 검증 체크리스트 제출 → 교사의 승인(대출 실행)/반려, 학생의 분할·전액 상환(조기 상환 포함)
- 소득세·사업 세금: 교사가 세율(각 0~20%) 설정, 정산월에 실제 지급된 월급/사업 매출 합계를 과세 대상으로 미리보기 → 확정, 공동기금 계좌로 징수
- 과태료: 누구나(학생·교사) 규칙 위반 신고 → 교사가 확인 후 과태료 부과(금액 지정) 또는 기각(사유 필수) → 부과 시 학생 계좌에서 즉시 차감, 공동기금으로 귀속
- 공동기금: 소득세·사업 세금·과태료가 모두 모이는 계좌, 교사가 잔액 확인 후 직접 지출(내용·금액 입력, 즉시 실행)
- 경제 통계: 운영 현황 화면에 유통 중인 화폐 총액·학생 평균 잔액·사업 계좌 합계·공동기금 잔액 표시
- 사업·상품 등록(교사), 학생의 즉시 구매(가격·재고·잔액 서버 검증, 재고 경쟁 시 하나만 성공)
- 사업을 맡은 학생은 자기 사업의 상품을 직접 추가·수정하고 매출(계좌 잔액·거래 내역)을 볼 수 있음(사업 생성·종료는 교사 전용)
- 시민광장: 직업/사업/규칙/행사/학교개선 구조화 제안서 제출(초안 저장·수정 가능) → 교사가 투표 개시(마감·참여율·찬성 기준 설정) → 1인 1표 비공개 투표 → 교사 집계 → 승인 시 직업/사업은 실제 생성, 규칙/행사/학교개선은 결정 자체가 결과 → 제안마다 시민 의견(댓글) 작성 가능
- 사진 인증 업무: 브라우저에서 사진을 압축해 임시 제출 → 교사 검토 후(승인/반려 모두) 원본 자동 삭제, 24시간 만료. 원본은 지워도 몇 번째 시도가 언제 어떻게 심사됐는지는 감사 로그에 남음
- 운영: 감사 로그(제안 결정·사업 생성·월급 지급·소득세·사업 세금·과태료·공동기금 지출·사진 인증 심사), 학생 학년/반/학적 상태(졸업·전출) 수정, 운영 현황 대시보드(참여 현황 + 경제 통계)
- 학교별 데이터 격리, 서버 시각/필드 검증, 중복 신청 방지
- 학생 명단은 커서로 이어서 조회 가능(100명 단위 "더 보기")
- 승인과 배정 트랜잭션, 핵심 직업 해제/삭제 금지, 종료 직업 신규 배정 금지
- 제공된 배경 및 국·직업 아이콘, 지도형 학생 홈, 태블릿/모바일 레이아웃

## 후속 구현

원본 계획 8단계까지 핵심 기능을 한 차례씩 연결했고, 이후 백로그로 남아 있던 심화 기능(국 이름 편집·직업 정원·배정/신청 이력·업무 제출 이력·명단 페이지 조회·대출 분할 상환)도 모두 연결했습니다(`docs/DECISIONS.md` D-85~D-91). 남은 것은 더 다듬는 일입니다.
목록은 대부분 최대 100건입니다. 학생 명단만 커서로 이어서 전체를 조회할 수 있고(D-90), 나머지 목록(직업·업무·제안 등)은 학급 규모에서 100을 넘길 일이 거의 없어 아직 첫 100건만 보여줍니다 — 필요해지면 같은 방식을 그대로 적용할 수 있습니다.
신청은 반려된 뒤에는 같은 직업에 다시 신청할 수 있고, 반려된 이전 신청 내용은 이력으로 남습니다(D-86). 승인 대기 중이거나 이미 승인된 신청은 재신청할 수 없습니다.
배정 문서는 학생/직업의 현재 상태를 나타내며, 종료되는 순간의 기간(시작~종료 시각)은 이력으로 보존됩니다(D-86). 직업에는 정원을 설정할 수 있고, 정원이 차면 배정이 거부됩니다(D-88).
업무는 인증 방식 중 결과물 제출(artifact)·사진 제출이 실제로 동작합니다(자동 인증은 다음 단계). 업무 문서 자체는 여전히 최신 제출 내용만 담지만, 시도마다의 제출 텍스트는 별도 이력으로 보존되어 이전 시도 내용을 다시 볼 수 있습니다(D-89) — 사진 바이트 자체는 여전히 보존하지 않습니다(D-37).
금융은 월급 정산·즉시 구매·저축(가입·만기 정산)·대출(신청·검토·승인·분할/전액 상환)·소득세·사업 세금·과태료·공동기금 지출·경제 통계까지 구현되어 있습니다(`docs/DECISIONS.md` D-17~D-21, D-48~D-55, D-59~D-74, D-91). 대출은 한 번에 전액을 갚거나 여러 번에 나눠 갚을 수 있고, 조기 상환도 항상 가능했습니다(D-52, D-91). 저축 만기 전 정산은 화면뿐 아니라 Rules에서도 막습니다 — 계약의 `maturityAt`이 지나지 않았으면 항목을 조작해도 정산 트랜잭션 자체가 거부됩니다(D-84). 대출 검토자는 교사가 활동 중인 학생 아무나 지정할 수 있으며 "은행원" 직업 보유를 강제하지 않습니다(의도된 설계, D-52). 소득세·사업 세금 모두 잔액이 아니라 그 정산월에 실제로 발생한 소득/매출에만 매깁니다. 과태료 신고 원문은 신고자와 교사만 볼 수 있고, 대상 학생은 결과(계좌 거래 내역)만 봅니다.
사업 운영 학생의 자기 상품 관리·매출 열람은 구현되어 있습니다(`docs/DECISIONS.md` D-22~D-25, D-63~D-65). 사업 생성·종료는 여전히 교사 전용입니다. 상품은 1개씩만 구매할 수 있습니다.
시민광장은 직업/사업/규칙/행사/학교개선 제안, 초안 저장, 시민 의견(댓글)을 모두 지원합니다(`docs/DECISIONS.md` D-27~D-32, D-75~D-78). 초안은 학급 전체에 공개됩니다(작성자만 수정 가능). 댓글은 수정·삭제할 수 없습니다.
사진 인증은 최신 1장만 보존합니다(재제출하면 이전 사진은 사라짐) — 다만 몇 번째 시도가 언제 어떻게 심사됐는지는 감사 로그로 남습니다(`docs/DECISIONS.md` D-33~D-37, D-79).
감사 로그는 제안 결정·사업 생성·월급 지급·소득세·사업 세금·과태료·공동기금 지출·사진 인증 심사에 있습니다. 로그인 계정 발급/비활성화는 앱 밖 관리 도구 영역입니다(`docs/DECISIONS.md` D-38~D-43).
학교별 국 이름 편집(D-85)은 4개 국 자체의 신설·삭제가 아니라 표시 이름만 바꿉니다.

학생 실명 명단, 사진, 금융정보는 배포 자산에 포함하지 않습니다.
