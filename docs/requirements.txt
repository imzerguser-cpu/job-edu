마동초등학교 「마동시민 작은 사회」 웹앱 기획·운영 계획

1. 프로젝트 목적
마동초등학교 학생들이 학교 안에서 하나의 작은 사회를 직접 구성하고 운영한다.
학생은 시민 → 직업 → 업무 → 보상 → 경제활동 → 시민 의사결정 → 새로운 직업·사업의 순환을 경험한다.
직업교육, 경제·금융교육, 민주시민교육, 공동체교육, 디지털 리터러시를 학교생활 속에서 경험하는 것이 목표다.

2. 지속가능성
학생 수 감소에 대비하여 많은 직업을 고정하지 않는다.
핵심국은 유지하고 세부 직업은 학생 수에 따라 통합·분리한다.
핵심국:
- 경제·관리국
- 미디어·디지털국
- 생활·환경국
- 문화·기획국
학생 수가 적어지면 한 학생이 여러 직업을 맡을 수 있다.

3. 직업 체계
경제·관리국: 은행, 세무·회계, 상점/매점, 카페, 부동산, 사업 관리
미디어·디지털국: 기자, 사진작가, 작가, 웹툰작가, 화가, 태블릿 관리, 디지털 관리자, DJ
생활·환경국: 도서관, 환경관리, 식물관리, 안전관리, 규칙관리, 우유 배달, 택배, 가정통신문, 게시판 관리
문화·기획국: 행사기획, 음악, 가수, 댄서, 보드게임, 기타 문화·놀이 직업
세부 직업은 학생 수와 학교 상황에 맞게 운영한다.

4. 핵심 직업과 시민 직업
핵심 직업은 작은 사회 유지에 반드시 필요한 역할이며 학생이 임의로 삭제할 수 없다.
시민 직업은 학생들이 새로운 직업을 제안할 수 있고 승인되면 실제 직업으로 등록한다.

5. 직업 상태
준비 중 / 모집 중 / 운영 중 / 일시 중지 / 운영 종료
운영 종료 직업 데이터는 보존하되 별도의 역사관 기능은 만들지 않는다.

6. 마동시민
모든 학생은 시민 계정을 가진다.
태블릿에서 시민증을 확인한다.
시민증: 이름, 학년/반, 시민 ID, 현재 직업, 소속국 등.
필요한 개인정보만 저장하고 불필요한 공개를 제한한다.

7. 태블릿 중심 운영
시민 확인 → 직업 신청 → 직업 배정 → 오늘의 업무 확인 → 업무 수행 → 업무 인증 → 보상 → 경제활동.
종이 장부 사용은 최대한 줄인다.

8. 학생 메인 화면
시민증 / 내 직업 / 오늘의 업무 / 업무 인증 / 내 마동 / 은행 / 저축 / 대출 / 시장·사업 / 시민광장 / 투표 / 알림.

9. 업무 시스템
각 직업은 실제 업무를 가진다.
예: 농부는 화분 상태 확인·물주기·사진 인증, 기자는 인터뷰·기사 작성·결과물 제출, 은행원은 금융 거래·이자 지급 내역·이상 거래 검증.
업무는 일회성·반복성·기간형 등을 지원한다.

10. 업무 인증
① 시스템 자동 인증: 저축, 대출 상환, 매점 판매, 도서 대여, 금융 검증 등.
② 사진 인증: 식물, 환경, 우유 배달, 택배, 안전 점검 등.
③ 결과물 제출: 기사, 웹툰, 글, 그림, 행사기획서 등.
단순히 완료 버튼만 눌러 보상을 받는 구조는 피한다.

11. 사진 인증
사진은 장기 보관 목적이 아니다.
사진 제출 → 인증 → 업무 완료 → 불필요한 사진 삭제를 기본 방향으로 한다.
Padlet·QuizN 등의 외부 서비스를 검토할 수 있으나 기본 시스템은 자체 인증 기능을 우선한다.

12. 학교 화폐
가상의 학교 화폐를 사용한다. 현재 이름은 '마동'.
다른 학교에서도 사용할 수 있도록 화폐 이름과 기호는 교사가 설정할 수 있게 한다.
학생은 마동을 벌고, 쓰고, 저축하고, 빌리고, 갚고, 이자를 받고, 이자를 내고, 세금을 낸다.

13. 은행
은행은 작은 사회의 핵심 시스템이다.
계좌 / 입금 / 출금 / 송금 / 저축 / 대출 / 상환 / 이자 / 월급 / 금융 검증을 관리한다.
은행원은 프로그램이 자동 처리한 금융 업무를 검증한다.

14. 저축 이율
연이율이 아닌 월이율을 사용한다.
단기저축: 월 5%, 권장 1~3개월
장기저축: 월 10%, 권장 4개월 이상
실제 금융시장 이율이 아닌 교육용 이율이다.

15. 대출 이율
단기대출: 월 6%, 권장 1~3개월
장기대출: 월 12%, 권장 4개월 이상
이율과 기간은 교사가 변경할 수 있어야 한다.

16. 이자 계산
초기에는 단리 방식을 사용한다.
저축 이자 = 원금 × 월이율 × 저축개월수
예: 100마동 × 5% × 3개월 = 15마동
대출 이자 = 대출원금 × 월이율 × 대출개월수
예: 100마동 × 6% × 3개월 = 18마동
복리는 기본 방식으로 사용하지 않는다.

17. 금융상품 설정
교사가 상품명, 유형, 저축/대출 여부, 월이율, 최소·최대 금액, 최소·최대 기간, 중도해지, 만기 조건, 이자 지급 방식·주기 등을 설정할 수 있게 한다.

18. 금융 거래 원장
잔액만 저장하지 않고 모든 거래를 원장 형태로 기록한다.
거래 유형 예:
SALARY, DEPOSIT, WITHDRAW, TRANSFER, INTEREST, LOAN, LOAN_REPAYMENT, TAX, FINE, PURCHASE, SALE, REFUND, ADJUSTMENT
기존 거래를 직접 삭제·수정하지 않고 정정 거래를 새로 생성한다.

19. 이자 지급
만기 또는 정해진 지급일에 시스템이 이자를 계산한다.
잔액만 증가시키지 않고 INTEREST 거래를 생성한다.

20. 대출
대출 신청 → 목적 작성 → 상환 계획 작성 → 은행원 검토 → 필요 시 교사 승인 → 대출 실행 → 계좌 입금 → 거래원장 생성.
원금, 이자, 기간, 상환액, 남은 원금, 상환 기록 등을 관리한다.

21. 은행원의 금융 검증
대상 학생, 원금, 이율, 이자, 중복 지급 여부 등을 확인하는 업무를 제공한다.
검증 완료 자체가 실제 직업 업무가 된다.

22. 월급
교사가 직업별 급여를 설정한다.
월급 계산 → 지급 → 계좌 반영 → 거래원장 생성 → 은행원 검증.

23. 세무·회계
소득세, 사업 세금, 공동기금, 재정 장부, 경제 통계를 관리한다.
세율은 교사가 설정하고 학생이 임의로 세금을 부과하지 못한다.

24. 과태료
규칙 위반 보고 → 교사 확인 → 과태료 결정 → 시스템 생성 → 학생 납부 → 금융 기록.
학생이 임의로 과태료를 부과하지 못한다.

25. 사업
학생이 작은 사업을 만들고 운영할 수 있다.
예: 매점, 카페, 보드게임 대여점, 사진관, 디자인 스튜디오, 학생 제안 사업.
사업자, 직원, 상품, 가격, 매출, 비용, 순이익, 사업계좌, 세금 등을 관리한다.

26. 시민제안
새로운 직업, 사업, 서비스, 규칙, 학교 개선 아이디어, 행사 등을 제안할 수 있다.

27. 직업추천서
직업명, 업무, 필요성, 구체적 업무, 도움을 받는 사람, 예상 급여, 필요한 도구, 추천 이유 등을 작성한다.

28. 사업제안서
사업명, 판매/서비스, 고객, 가격, 초기 자본, 인력, 예상 수익·비용, 장점, 예상 문제와 해결 방법 등을 작성한다.

29. 시민 투표
제안 등록 → 시민 의견 → 투표 → 교사 검토 → 승인/반려 → 실제 직업·사업·제도 생성.
투표 기준은 교사가 설정한다.

30. 교사 관리자
교사는 전체 사회의 관리자이자 최종 감독자다.
학생, 학급, 직업, 업무, 급여, 금융, 세금, 대출, 사업, 시민제안, 투표, 인증, 통계, 시스템 설정을 관리한다.
안전·개인정보·금융·제도 변경은 교사가 최종 권한을 가진다.

31. 자동화와 승인
프로그램 자동 처리: 이자 계산, 거래 기록, 월급 계산, 저축, 대출 상환 계산, 매점 판매, 업무 상태 변경.
학생 처리: 직업 업무, 금융 검증, 사업 운영, 콘텐츠 제작, 시민 제안, 투표.
교사 최종 승인: 핵심 금융 설정, 세율, 과태료, 새로운 직업·사업, 규칙, 중요한 금융 오류 수정.

32. 다른 학교 지원
마동초등학교 전용 하드코딩을 하지 않는다.
예: schoolId, schoolName, communityName, currencyName, currencySymbol.
다른 학교 교사가 학교명, 사회 이름, 화폐 이름, 직업, 급여, 이율, 세율, 업무 등을 설정할 수 있도록 한다.

33. Firebase 및 무료 운영
Firestore를 주요 DB 후보로 사용한다.
카드 등록이 필요한 유료 방식은 사용하지 않는다.
유료 Cloud Functions에 의존하지 않는다.
이미지 저장과 실시간 DB 사용을 최소화한다.
불필요한 데이터를 저장하지 않는다.
실제 개발 전에 당시 Firebase 무료 정책을 확인한다.
무료로 구현할 수 없는 기능은 유료 기능을 바로 쓰기보다 대체 방법을 먼저 검토한다.

34. 개인정보 보호
필요한 정보만 수집, 학생 금융정보 비공개, 다른 학생 개인정보 접근 제한, 사진 장기 저장 최소화, 학생 사진 외부 공개 금지, 학생·교사 권한 분리를 기본으로 한다.

35. 화면과 권한
학생 화면은 쉽고 직관적으로 만든다.
교사 화면은 관리와 데이터 확인 중심으로 만든다.
학생에게 관리자 기능이 노출되지 않도록 권한을 분리한다.

36. 학년별 역할
1~2학년: 도서관, 식물, 우유, 환경, 물품 전달 등 생활 중심.
3~4학년: 매점, 기자, 사진, 디지털, 행사 보조 등 실무 중심.
5~6학년: 은행, 세무·회계, 사업관리, 시민제안, 금융검증 등 관리 중심.
학년 제한은 강제하지 않고 교사가 수정할 수 있게 한다.

37. 핵심 사회 순환
시민 → 직업 → 업무 → 인증 → 보상 → 은행 → 저축/소비/사업 → 세금 → 공동체
시민은 시민 제안 → 시민 투표 → 교사 승인 → 새로운 직업/사업을 통해 사회를 변화시킨다.

38. 개발 전략
전체 설계는 먼저 확정하되 실제 코드는 기능별로 단계적으로 구현한다.
전체 설계 전달 → 기능별 구현 → 테스트 → 문제 수정 → 다음 기능 구현.
설계는 전체적으로, 개발은 안정성을 위해 단계적으로 진행한다.

39. 권장 개발 순서
1단계 기본 구조: 프로젝트, Firebase, 로그인, 학교, 학생, 시민
2단계 직업: 직업, 신청, 배정, 국, 학년 설정
3단계 업무: 생성, 배정, 반복 업무, 완료, 인증, 보상
4단계 은행·금융: 계좌, 거래원장, 월급, 저축, 이자, 대출, 상환, 금융 검증
5단계 경제: 세금, 과태료, 상점, 사업, 매출, 비용
6단계 시민사회: 직업 제안, 사업 제안, 시민 투표, 교사 승인
7단계 사진·콘텐츠 인증: 사진 제출, 결과물 제출, 인증, 자동 삭제
8단계 통계·운영 도구: 교사 대시보드, 직업 통계, 경제 통계, 업무 통계, 시민 참여율

40. 최종 목표
학생이 태블릿을 켜고 '나는 마동시민이다'라고 시작한다.
오늘의 일을 확인하고 직업으로 실제 일을 하며 결과를 인증하고 마동을 받는다.
저축·소비·대출·사업·세금·공동체 활동에 참여하고 새로운 직업이나 사업을 제안하며 다른 시민의 제안에 투표한다.
궁극적으로 학생이 '학교에서 주어진 일을 하는 사람'이 아니라 '학교라는 사회를 함께 만들어가는 시민'이라는 경험을 하게 한다.

핵심 원칙:
학생 수가 줄어도 유지되고, 학생이 직접 새로운 직업과 사업을 만들 수 있으며, 실제 경제활동까지 연결되는 학교용 작은 사회를 웹앱으로 구현한다.
